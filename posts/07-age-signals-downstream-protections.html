Age signals and downstream protections: one model, many safeguards

Age ML is not a leaderboard AUC. It is an API that teen mode, consent, and ads secretly depend on.

Teams talk about “the age model” as if it were a single number in a notebook. In production it is a versioned service with consumers nobody listed until one threshold move breaks teen mode or consent routing in a new jurisdiction. Unified age classification is platform infrastructure, not a one-off Kaggle slice.

Outputs should be distributions, not cliff edges

Hard-thresholding a probabilistic world creates audit nightmares. Ship buckets with confidence, provenance (declared vs inferred), and explicit override hooks for human review.

  • Policy bands (child / teen / adult) with Legal-defined cut points.
  • Calibration **per region**—global models hide slice failures.
  • Consumer registry: which feature uses which score version since when.

Evaluation teams should publish internally

Error typeWhy it hurtsWeight in review
Child classified adultCOPPA / consent bypassHighest
Teen classified adultWeaker teen defaultsHigh
Adult classified teenFriction, false restrictionsMedium

Report recall on under-13 before you report overall accuracy. Executives understand “missed minors” faster than macro-F1.

Shadow scoring before threshold politics

Every model bump should run shadow mode against production: same inputs, new scores logged, no user impact until PM/Legal sign off on downstream diffs. Document changelogs like API breaking changes—because they are.

Downstream map (PM exercise)

Draw one page: age score → teen mode → consent routing → ad personalization → DM restrictions. If DS cannot fill that page, you do not have a unified system—you have a research project.

For PMs — before changing a threshold

  • Which states’ flows depend on this band?
  • What is rollback time if support spikes?
  • Did Legal re-review the consumer list?
